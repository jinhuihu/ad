# Android APK 在线编译指南

## 🎯 概述

由于本地 Android SDK 36 存在问题，我们提供多种在线编译方案，无需本地配置 SDK。

---

## 方案 1: GitHub Actions（推荐⭐）

### 优点
- ✅ 完全免费（公开仓库）
- ✅ 自动配置 Android SDK
- ✅ 编译速度快（5-10 分钟）
- ✅ 支持手动触发和自动触发
- ✅ 可下载编译好的 APK

### 使用步骤

#### 步骤 1：将代码推送到 GitHub

```bash
cd /Users/hujinhui/project/sb

# 如果还没有 GitHub 仓库，需要先创建
# 1. 访问 https://github.com/new
# 2. 创建一个新仓库（可以是私有或公开）

# 添加 GitHub 作为远程仓库
git remote add github https://github.com/你的用户名/仓库名.git

# 或者如果已有 GitHub 仓库，修改现有的 origin
# git remote set-url origin https://github.com/你的用户名/仓库名.git

# 提交 GitHub Actions 配置文件
git add .github/workflows/
git commit -m "添加 GitHub Actions 在线编译配置"

# 推送到 GitHub
git push github master
# 或
git push origin master
```

#### 步骤 2：触发编译

**方法 A：自动触发（推送代码时）**
```bash
# 任何推送到 master 分支的操作都会自动触发编译
git push github master
```

**方法 B：手动触发**
1. 访问你的 GitHub 仓库
2. 点击顶部的 **Actions** 标签
3. 选择 **Android CI - 编译 APK** 工作流
4. 点击右侧的 **Run workflow** 按钮
5. 点击绿色的 **Run workflow** 确认

#### 步骤 3：下载编译好的 APK

1. 在 Actions 页面，点击最近的工作流运行
2. 等待编译完成（绿色✅表示成功）
3. 滚动到页面底部的 **Artifacts** 部分
4. 点击 **app-debug** 下载 APK 文件
5. 解压 zip 文件，获得 `app-debug.apk`

### 两个工作流说明

我已经创建了两个工作流：

1. **android-build.yml** - 使用 SDK 36 编译（默认配置）
2. **android-build-sdk33.yml** - 使用 SDK 33 编译（备用方案）

如果 SDK 36 编译失败，可以手动触发 SDK 33 版本。

## 方案 2: GitLab CI/CD

如果你使用 GitLab 或自建的 GitLab 实例：

### 创建 `.gitlab-ci.yml`

```yaml
image: openjdk:11-jdk

variables:
  ANDROID_COMPILE_SDK: "33"
  ANDROID_BUILD_TOOLS: "33.0.1"
  ANDROID_SDK_TOOLS: "9477386"

before_script:
  - apt-get --quiet update --yes
  - apt-get --quiet install --yes wget unzip
  
  # 下载 Android SDK
  - wget --quiet --output-document=android-sdk.zip https://dl.google.com/android/repository/commandlinetools-linux-${ANDROID_SDK_TOOLS}_latest.zip
  - unzip -q android-sdk.zip -d android-sdk-linux
  - export ANDROID_SDK_ROOT=$PWD/android-sdk-linux
  - export PATH=$PATH:${ANDROID_SDK_ROOT}/cmdline-tools/latest/bin:${ANDROID_SDK_ROOT}/platform-tools
  
  # 安装 SDK
  - mkdir -p ~/.android && touch ~/.android/repositories.cfg
  - yes | sdkmanager --sdk_root=${ANDROID_SDK_ROOT} --licenses || true
  - sdkmanager --sdk_root=${ANDROID_SDK_ROOT} "platforms;android-${ANDROID_COMPILE_SDK}" "build-tools;${ANDROID_BUILD_TOOLS}" "platform-tools"
  
  # 授予权限
  - cd AndroidCaptchaSolver
  - chmod +x ./gradlew

stages:
  - build

build_debug:
  stage: build
  script:
    - cd AndroidCaptchaSolver
    - ./gradlew assembleDebug
  artifacts:
    paths:
      - AndroidCaptchaSolver/app/build/outputs/apk/debug/app-debug.apk
    expire_in: 1 week
```

## 方案 4: 使用 Docker 本地编译（无需本地 SDK）

如果你安装了 Docker：

```bash
# 使用 Docker 编译
docker run --rm -v "$PWD":/project -w /project/AndroidCaptchaSolver \
  mingc/android-build-box:latest \
  bash -c "chmod +x gradlew && ./gradlew assembleDebug"

# 编译完成后，APK 位于：
# AndroidCaptchaSolver/app/build/outputs/apk/debug/app-debug.apk
```

## ❓ 常见问题

### Q: GitHub Actions 编译失败怎么办？

A: 查看错误日志，如果是 SDK 36 问题，手动触发 `android-build-sdk33.yml` 工作流。

### Q: 需要签名的 Release 版本怎么办？

A: 需要在 GitHub Secrets 中添加签名信息，或者只使用 Debug 版本（功能完全相同）。

### Q: Docker 方案需要什么配置？

A: 只需要安装 Docker Desktop，其他配置都在容器中自动完成。

### Q: 私有仓库能用 GitHub Actions 吗？

A: 可以，但免费账户有分钟数限制（每月 2000 分钟）。
